# Array argument hints and opaque reference reads

## Intent

Array-valued benchmark arguments must compile with their exact array type and retain the same input-barrier guarantees as other reference arguments. Type capture must not introduce reflection, copy arrays, box their elements, or change the subject's result.

## Problem and context

[GitHub issue #156](https://github.com/hugoduncan/criterium/issues/156) reports that `measured/expr` fails for array-typed locals:

```clojure
(let [xs (long-array [1 2 3])]
  (measured/expr (alength xs)))
;; Unable to resolve classname: long[]
```

Before this fix, `criterium.measured.impl/tag-meta` derived a symbol from `Class/getCanonicalName`. Array names such as `long[]` and `user.R[]` are not valid Clojure class hints. This helper also supplies metadata for evaluated non-local arguments and generated arguments through `criterium.arg-gen/arg-metas-from-example`.

Before this fix, the input-barrier classifier sent string tags and canonical array-name symbols to a plain-binding fallback. A string-only compilation fix would therefore leave arrays without the opaque input barrier. An array is a reference value, including when its elements are primitive. The existing `AtomicReference` cell can store that reference without copying the array or boxing its elements.

## Selected design

Inferred array hints use JVM-name strings, such as `"[J"`, `"[Luser.R;"`, and `"[[J"`. These retain the exact component class and number of dimensions. Valid string class hints participate in the reference-cell contract. Existing explicit array hints, including `^longs` and descriptor strings, retain their meaning.

The existing type-capture boundary owns compiler metadata. The existing cell taxonomy owns barrier selection. Arrays use the existing reference-cell abstraction; they do not need a new cell kind, Java helper, or runtime array inspection.

Non-array inference and scalar conversions retain their current behaviour. There is no compatibility requirement for invalid canonical array hints generated by the defect.

### Alternatives considered

- JVM-name symbols also compile and already select reference cells. String metadata is preferred because it has a normal readable representation, including object-array descriptors with semicolons.
- Array aliases such as `longs` and `objects` are familiar, but a generic `objects` hint loses exact reference component types and dimensions.
- Omitting hints restores compilation but can add reflection and change the work being measured.
- Retaining plain bindings fixes only compilation and leaves array inputs outside the input-barrier contract.

## Scope and invariants

- Primitive arrays of all eight element types, reference arrays, arrays of records or other user-defined classes, and multidimensional arrays.
- Inferred local arguments, evaluated non-local arguments, generated arguments, and explicit array hints.
- Exact array identity and contents remain unchanged by argument transport. The barrier does not make array contents immutable or control mutations by the benchmark subject.
- Each captured array reference is stored once and its cell escapes once before timing. Each subject evaluation reads the reference opaquely and retains the exact type hint.
- No array copy, element boxing, or per-iteration cell allocation is introduced.
- Existing scalar and callable behaviour remains unchanged.
- Tests and documentation describe arrays as references, not as values that require primitive cells.

Out of scope: callable-path barriers (#157), argument pools (#158), baseline reporting (#159), general changes to expression factoring or type inference, and guarantees about arbitrary concurrent mutations of array contents.

## Acceptance criteria

1. The issue's `bench` reproduction compiles and completes. Equivalent `measured/expr` checks return the correct result for single and repeated evaluations.
2. Inferred metadata equals the exact JVM-name string for each supported array shape. Non-array metadata remains unchanged.
3. Local, non-local, and generated array arguments compile and return correct results. Explicit alias and descriptor-string hints also work.
4. Representative `alength`, primitive `aget`, and statically typed array-parameter calls compile without new reflection warnings. Coverage includes every primitive array type, object arrays, a user-defined component class, and multidimensional arrays.
5. Array arguments use the reference-cell path. Structural checks establish one setup store, one setup escape before timing, and opaque reads for the initial subject evaluation and loop evaluations. Exact array identity is preserved.
6. Tests that require arrays to bypass the barrier are replaced with the new contract. Callable-path checks remain valid and separate.
7. Focused compiler and functional checks pass on Clojure 1.11.4 and 1.12.4. Relevant measured and arg-gen suites pass. Existing barrier checks pass in runtime and compiler-blackhole modes where supported; timing thresholds are not used to prove type correctness.
8. User-facing release notes and affected barrier documentation no longer describe array hints as a pending compilation defect or arrays as requiring a non-opaque fallback.

## Evidence and limits

The analysis reproduced the defect on Clojure 1.12.4 / JDK 25. Focused compiler probes on Clojure 1.11.4 and 1.12.4 accepted JVM-name strings after `AtomicReference.getOpaque` for all primitive array types, object arrays, `String[]`, and `long[][]`, without reflection warnings for `alength`. These probes were not a full suite or a JIT behaviour test.
